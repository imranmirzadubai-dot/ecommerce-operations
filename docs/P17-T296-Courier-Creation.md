# P17-T296 — Courier Creation

Adds the first trusted state-changing command for courier master-data creation.

## Contract

- The existing `public.shippers` table remains the courier master.
- `public.create_courier(...)` creates one courier and returns its immutable UUID, generated `courier_code`, name, contact fields, active state, and timestamps.
- `courier_code` is generated by the existing `public.shipper_code_seq`; callers cannot supply or override it.
- `name` is required, trimmed, and bounded to 200 characters. The existing database uniqueness constraint remains authoritative for duplicate names; broader duplicate/business rules are intentionally deferred to T302.
- Contact fields are optional and normalized by trimming blank values to NULL. Contact email is lower-cased server-side when supplied.
- New couriers default to `active = true`.
- The command is Admin-only and requires an authenticated active Admin through the existing `public.app_role()` boundary.
- Retries use the existing command-idempotency foundation. Reusing an idempotency key with a different request hash fails closed; a completed retry returns the original result without creating another courier.
- The operation records a privileged `audit_logs` event with before/after data.
- No direct browser write privilege is added to `public.shippers`.
- No production data mutation is part of T296.

## Deliberately deferred

- Courier edit — T300.
- Duplicate/business-rule enforcement beyond the existing name uniqueness constraint — T302.
- Operational configuration — T304.
- Order-level courier relationship and assignment — T305–T307.
- Tracking/API ownership and credentials — T309–T314.
